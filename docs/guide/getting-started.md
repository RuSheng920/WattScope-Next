# 安装与上手

从下载到第一次导出记录，大约十分钟。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Android 13 及以上 |
| 平台 | 高通平台，且厂商 BSP 开放 QPT 节点（`/sys/class/powercap/qpt`） |
| 权限 | 已 root（KernelSU / Magisk / APatch），并能授予 root 权限 |
| 悬浮窗 | 需要悬浮球或 OSD 时开启 |

没有 QPT 节点也能装、也能用，只是没有分区功耗数据，只剩频率、占用、温度与 FPS。详见[常见问题](/guide/faq#没有-qpt-节点还能用吗)。

## 安装

1. 前往 [Releases](https://github.com/RuSheng920/WattScope-Next/releases) 下载最新版 `WattScope-Next-v*.apk`
2. 直接安装。应用 ID 为 `io.github.rusheng920.wattscope`，与原版 WattScope 互不冲突，可共存
3. 首次打开会进入**权限引导页**，不会在启动时弹一堆授权窗口

::: tip 只从 Releases 下载
APK 使用固定签名发布（证书 SHA-256 `a118fa78…47141d`）。第三方渠道的包请自行核验签名，不要盲目授予 root。
:::

## 首次授权

引导页会逐项列出所需权限，点进每一项可以直接跳到系统页面：

| 权限 | 用途 | 缺失后果 |
| --- | --- | --- |
| Root（KernelSU / Magisk） | 读取 QPT、cpufreq、thermal 等 sysfs 节点 | 除界面外几乎全部功能不可用 |
| 悬浮窗 | 悬浮球与 OSD 浮层 | 只能用应用内页面记录 |
| 通知 | 前台服务保活，显示记录状态 | 记录可能被系统回收 |
| 使用情况访问 | 识别当前前台应用（记录目标） | 悬浮球记录与 FPS 跟随失效 |
| 电池优化白名单 | 防止后台采样被冻结 | 息屏后曲线断点 |

授权状态**在页面可见期间每 1.5 秒自动复检**，在系统设置里改完返回即可看到变化，不用重启应用。

## 开始第一次记录

有两种方式：

::: code-group

```text [方式一：应用内]
仪表盘 → 点「开始记录」→ 切到目标应用使用 → 回到 WattScope → 点「停止记录」
```

```text [方式二：悬浮球]
设置里打开悬浮球 → 切到目标应用 → 单击悬浮球开始记录
→ 退出该应用时自动停止（单击也可以手动停止）
```

:::

悬浮球方式的好处是**记录目标自动锁定为你当时所在的应用**——悬浮球本身不抢焦点，所以「当前应用」就是你正在用的那个。

::: warning 5 秒宽限期
记录开始后的 5 秒内不做「已离开」判定。目标应用刚获得焦点时系统前台状态尚未稳定，这个宽限期能避免刚点开始就被判定为离开而自动停止。
:::

## 查看与导出

记录结束后进入「记录」Tab：

1. 列表里会多出一条记录，显示应用名、时长与平均功耗
2. 点进详情页可以看到分区功耗、频率、占用、温度、FPS 的完整曲线
3. 详情页支持**分区筛选**（只看 SOC / GPU / 某个核簇）与**导出**（JSON / CSV）

曲线顺序可以自己排：详情页「曲线」标题右侧的「排序」按钮，九个区块各带 ↑ / ↓，改动即时生效并持久化为全局设置。
